# 주소 검색 API

`GET /api/addresses/search?keyword={URL 인코딩한 검색어}`

기존 API와 동일하게 `Authorization: Bearer {accessToken}`이 필요합니다.
검색어 앞뒤 공백을 제거하며 1~100자를 허용합니다.

```json
{
  "code": "SUCCESS",
  "message": "요청이 성공적으로 처리되었습니다.",
  "data": [
    {"name": "홍익대학교 제2기숙사", "address": "서울 마포구 와우산로 94 홍익대학교", "x": 126.9256, "y": 37.5515}
  ]
}
```

위 결과는 응답 형식 예시이며 실제 검색 결과를 보장하지 않습니다.
건물번호가 포함된 도로명·지번 주소 형태는 카카오 주소 API를 우선 사용합니다. 도로명 뒤에 건물번호를 붙여 쓴 경우 해당 공백만 정규화합니다.
주소 API에서 검색에 실패하거나 유효한 결과가 없으면 기존 카카오 장소 키워드 검색으로 복구합니다. 장소명 입력은 기존 장소 검색만 사용합니다.
최대 5개 결과를 반환하며, 도로명 주소가 없으면 지번 주소를 사용합니다.
좌표는 WGS84 경도(x), 위도(y) 숫자입니다. 기존 등록 조건에 맞지 않는 결과는 제외합니다.
검색 결과가 없으면 `data: []`를 반환합니다. 검색으로 DB에 저장하지 않습니다.

프론트는 목록에서 사용자가 선택한 항목을 기존 `POST /api/addresses` 본문으로 전달합니다.
현재 프론트는 1초 간격 검색 스케줄러를 사용하며, 이전 검색 요청을 취소하고 최신 검색 결과만 반영합니다.
프론트의 공통 HTTP 요청 제한시간은 30초입니다. 응답 필드를 변경하지 않아 프론트 수정은 필수가 아닙니다.

## 서버 설정

카카오 개발자센터에서 카카오맵 사용 설정을 ON으로 설정한 앱의 REST API 키를 서버 환경변수로 설정하고 서버를 재시작합니다.

- `KAKAO_REST_API_KEY`

JavaScript 키나 어드민 키가 아닌 REST API 키를 사용합니다. 키를 프론트나 Git에 넣지 않습니다.
미설정 상태에서도 서버는 시작하지만 검색 호출은 HTTP 503 / A005를 반환합니다.
주소 API가 실패하거나 잘못된 응답을 반환하면 기존 장소 키워드 검색을 추가 시도합니다.
두 공급자 요청이 모두 실패하면 503 / A005를 반환합니다. 두 요청 중 성공한 검색 결과가 비어 있으면 `data: []`를 반환합니다.
공백 또는 100자 초과 검색어는 400 / C002, 파라미터 누락은 기존 공통 예외 처리에 따릅니다.
각 카카오 요청의 연결 제한시간은 1초, 읽기 제한시간은 2초입니다. 주소 검색과 장소 검색의 순차 수행 시 연결/읽기 제한시간의 단순 합계는 최대 약 6초이지만 DNS·직렬화·스케줄링 등을 포함한 서버 전체 요청의 하드 데드라인은 아닙니다. 자동 재시도는 하지 않습니다.
이 클라이언트의 타임아웃 변경은 역지오코딩에도 동일하게 적용됩니다. 역지오코딩은 실패 시 기존대로 null을 반환합니다.

이 API는 주소 검색과 업체·기관 등의 장소 검색을 모두 지원합니다. 오타 교정, 별도 요청 횟수 제한 및 캐시는 포함하지 않습니다.
최종 배포 전 테스트 대상: 주소 API 정상·장애·빈 결과·잘못된 응답, 장소 검색 회귀, 좌표 유효성, 기존 인증·응답 필드 호환, 실제 카카오 키 설정 여부.
`main` 머지 시 배포 워크플로가 자동 실행되므로 PR 검증 중에는 머지하지 않습니다.
기존 transit 경로 검색 API는 변경하지 않습니다.

참고: https://developers.kakao.com/docs/ko/kakaomap/rest-api

외부 요청은 대한민국 좌표 범위(rect=124,33,132,39), 정확도순, 최대 5개로 제한합니다.
