# 카카오 경로의 서울 버스·지하철 첫차·막차 알림

## 지원 범위

- 카카오 경로 중 서울 BUS/SUBWAY 구간 합계 최대 5개와 WALK 구간을 지원한다. 버스↔버스, 버스↔지하철, 지하철↔지하철 환승을 처리한다. 지하철은 TAGO에서 역과 시간표를 찾을 수 있는 1~9호선이며 공항철도·GTX 등은 이번 범위 밖이다.
- 서울 API의 노선 유형 2~6(마을·간선·지선·순환·광역)만 허용한다. 경기·인천 노선은 서울 정류장을 경유해도 제외한다.
- 출발/도착 정류장은 서울 주변 좌표 범위 안에 있어야 하며 실제 API 검색 결과로 확인한다. 좌표 사각형만으로 서울 정류장이라고 판정하지 않는다.
- NORMAL 알림 계산은 유지한다. 기존 ODsay 첫·막차 계산은 누락된 구간의 시간표를 건너뛰지 않는다. 중간 운행편이 필요한 경우 확인된 구간별 시간표와 여유 시간을 사용한 보수적 계산으로 전환한다.

## 검증 및 계산

1. `getStationByPos`로 탑승·하차 정류장 주변 100m를 검색한다. 정류장 이름과 WGS84 거리를 확인한다.
2. `getRouteByStation`에서 버스 번호와 서울 노선 유형을 확인한다.
3. `getStaionByRoute`에서 탑승·하차 ID, 전체 경유 정류장 이름의 연속 순서, 중간 회차 여부를 확인한다. 일치하는 방향이 정확히 1개일 때만 허용한다.
4. `getBustimeByStation`의 `arsId`/`busRouteId`를 대조하고 `firstBusTm`/`lastBusTm`을 읽는다.
5. **알림 시각 = 정류장 첫차/막차 예정시각 − 탑승 전 도보시간 − 미리 알림 시간**이다. 하차 후 도보시간은 차감하지 않는다.

정류장 이름의 `(7번승강장)` 같은 승강장 표기와 `(중)` 표기는 비교할 때만 제거한다. 좌표 거리, 정류장 ID, 노선 순서, 회차 검증은 그대로 적용하므로 이름만으로 방향을 결정하지 않는다.

## 서울 버스 환승과 실시간 확인

- 등록 시 모든 버스 구간의 시간표를 확인한다. 등록 성공은 미래의 환승편 연결을 확정했다는 의미가 아니다.
- 첫차는 첫 교통수단의 첫차 시각에서 접근 도보와 5분의 여유를 차감한다. 막차는 각 구간의 막차에서 앞 구간 이동·도보·여유 시간을 뺀 후보 중 가장 이른 시각을 사용한다. 구간 이동에는 25%(최소 3분), 환승마다 추가 10분, 출발에 5분을 적용한다. 사용자 미리 알림 시간은 그 뒤 별도로 차감한다. 이는 조기 출발 추정이며 배차 지연에 대한 수학적 보장은 아니다.
- 기존 알림 스케줄러 주기마다 조회 구간 안에서 `getArrInfoByRouteAll`을 조회한다. 노선별 응답은 20초 캐시하며 동일 노선을 여러 구간/알림에서 공유한다. 첫·막차 기준 출발 시각 60분 이후에는 더 이상 조회하지 않는다. 조회는 기본 알림 시각보다 최소 60분(경로 이동시간이 더 길면 그 시간) 앞서 시작한다.
- 응답의 정류장 ID와 정류장 순번으로 방향을 맞춘다. 첫 번째·두 번째 차량의 `vehId`, `exps`, `mkTm`, `isLast`를 사용한다. `mkTm` 기준 90초 이상 지난 응답, 미래 30초 초과 응답, 만차 차량은 사용하지 않는다.
- 각 차량의 승차·하차 정류장 도착예정을 **동일 차량 ID**로 연결한다. 환승 도보를 더한 시각에 다음 차량을 탈 수 있는 조합을 계산하고, 보수적 기본 시각보다 더 일찍 출발해야 하는 경우에만 앞당긴다. 실시간 정보 때문에 알림을 뒤로 미루지 않는다.
- 첫차는 조회된 연결 중 가장 이른 출발, 막차는 막차 표시가 적어도 한 구간에서 확인된 연결 중 가장 늦은 출발을 선택한다. 모든 운행편이 제공되는 것이 아니므로 이는 관측된 운행편 기준이며 전체 운행편의 최적 경로 보장은 아니다.
- 실시간 도착예정은 예측값이다. 실제 정체·운행 변경으로 환승 결과가 바뀔 수 있다. 정보 부족·오래된 응답·조회 실패 시에도 보수적 기본 시각에 알림을 발송한다. 이미 확보한 기본 시간표조차 없는 경로는 임의 시각을 만들지 않고 T005/T006으로 처리한다.
- 기존 snapshot·outbox·중복 방지·발송 기한 처리를 재사용한다. 더 이른 시각으로 보정한 결과는 이후 정보가 부족해져도 늦추지 않는다.
- 환승 snapshot source는 `SEOUL_BUS_TRANSFER`이며 당시 정류장/노선 ID와 순번을 `provider_details`에 저장한다. 자정 이후나 서버 재시작 후에도 전날 snapshot에 저장된 매칭 정보로 조회하며 오늘 시간표를 어제 것으로 대체하지 않는다.

## 지하철 시간표

TAGO `SubwayInfo/GetKwrdFndSubwaySttnList`와 `GetSubwaySttnAcctoSchdulList`를 기존 공공데이터 키로 사용한다. 역 이름과 호선을 대조하고, 출발·다음·도착역 시간표의 방향 및 종착역 후보를 비교한다. 열차 ID가 제공되지 않으므로 동일 열차 연결을 확정하지 않으며, 여러 방향 후보가 남으면 더 이른 첫·막차를 사용하는 보수적 추정이다. 미래 운행편의 정확한 환승 보장은 하지 않는다.

공휴일 달력 연결 전에는 평일/토요일 시간표에 일요일·공휴일 시간표도 비교해 더 이른 경계 시각을 택한다. 00~02시 시간은 전날 운행일의 자정 이후로 해석한다. 역/시간표는 1시간 캐시하며 페이지를 모두 읽는다. 최대 5,000행을 넘거나 응답이 불완전하면 실패로 처리한다. 지하철 실시간 위치 API는 아직 연결하지 않았고 시간표 기반 보수적 알림을 사용한다.

생성·수정 시 시간표를 검증하고, 스케줄러가 운행일마다 다시 검증하여 snapshot 테이블에 저장한다. 단일 버스 source는 `SEOUL_BUS`이며 기존 예정시간 기반 처리를 유지한다. 환승 실시간 조회는 위 규칙을 적용한다.

서울 시간표 API는 **금일 정보**이며 요청에 날짜 인자가 없다. 미래 날짜의 시간표를 보장하지 않는다. 반복 알림도 해당 운행일에 조회 가능한 시간표만 사용한다. 타임스탬프에 다른 날짜가 들어 있거나 값이 없으면 거절한다. 시간만 제공된 막차가 첫차보다 이르면 다음 날로 처리하며 24시 이상 표기도 처리한다.

자정을 넘긴 막차는 전날 snapshot과 전날 반복요일을 기준으로 발송한다. 전날 snapshot이 없으면 오늘 응답을 어제 시간표로 대체하지 않는다. 따라서 전날 시간표 확보 전에 서버가 중단되었거나 자정 이후 처음 등록한 경우 직전 운행일 막차는 보장되지 않는다.

성공한 매칭·시간표 조회는 날짜와 경로별 30분 캐시를 사용한다. 오류 발생 시 전체 서울 시간표 클라이언트에 60초 재시도 대기를 적용한다. 캐시 최대 1,000개, HTTP 연결 3초/읽기 5초 제한이다.

## 응답과 설정

- 요청 형식은 기존 FIRST_TRANSIT/LAST_TRANSIT와 같다. targetArrivalTime은 생략 가능하다.
- 경로 후보 전체(provider, 정류장 목록, 양 끝 좌표 포함)를 routeDetails로 저장해야 한다.
- `422 T005`: 지원 범위 밖, 방향 불명확, 정류장/시간표 매칭 실패.
- `503 T006`: 서울 API 인증/한도/통신/잘못된 응답 등 조회 실패. 등록·수정은 저장되지 않는다.
- 정확한 환승을 확인할 수 없어 내부 계산에서 T007이 발생하면 보수적 계산으로 전환한다.
- 키: `publicdata.seoul.schedule-key`, 생략 시 기존 `publicdata.api.key` 사용. 키를 코드나 문서에 기록하지 않는다.
- 정류소 서비스 집계는 `SEOUL_STATIONS`, 노선별 정류장 조회는 `SEOUL_ROUTES`다. 실제 승인 한도는 각각 `API_DAILY_LIMIT_SEOUL_STATIONS`, `API_DAILY_LIMIT_SEOUL_ROUTES`로 지정한다.
- V17 마이그레이션은 `notification_schedule_snapshots.provider_details` TEXT nullable 컬럼을 추가한다. 기존 행은 유지한다.
- 계산 버전이 바뀌어 기존 계산 결과를 재사용하지 않도록 snapshot 해시를 갱신했다. 배포 직후 전날의 구버전 snapshot은 사용하지 않으므로 자정 이후 배포 시 직전 운행일 알림은 보장하지 않는다. outbox의 날짜별 중복 방지는 유지한다.

## 운영 전 확인

2026-09-18 승인 반영 후 로컬 키로 152번 서울역 정류장의 노선 조회·첫막차 시간표·실시간 도착정보가 모두 정상(headerCd=0) 응답함을 확인했다. 시간표는 `063348`/`011107`, 도착정보는 `mkTm`, `staOrd`, `exps1/2`, `isLast1/2` 필드를 제공했다. 배포 서버의 키/설정은 별도로 확인해야 하며 실제 첫막차 시간대 환승 푸시 수신까지 검증한 것은 아니다.

같은 키로 TAGO 서울역 역 검색 및 4호선 시간표 조회도 정상(resultCode=00) 응답했다. 실제 전체 경로 매칭 검증용 임시 실행 명령은 권한 요청이 거절되어 실행하지 않았다. API별 응답 확인과 자동 테스트 결과를 실제 운행 시간대 수신 검증으로 간주하지 않는다.

T006 진단 로그는 API 경로, HTTP 상태, 예외 종류, 숫자 오류 코드만 남긴다. 키가 들어간 요청 URL이나 예외 전문은 출력하지 않는다.

- [서울특별시 정류소정보조회 서비스](https://www.data.go.kr/data/15000303/openapi.do): getStationByPos, getRouteByStation, getBustimeByStation
- 서울특별시 노선정보조회 서비스: getStaionByRoute (기존 서울 노선 동기화에서 사용)

공식 시간표 설명: [서울 정류소별 노선 첫차/막차 예정시간](https://data.seoul.go.kr/dataList/OA-15334/L/1/datasetView.do). 현재 명세의 시간 필드 이름과 '금일' 의미는 공공데이터포털의 상세 기능 getBustimeByStationList에서 확인했다.
